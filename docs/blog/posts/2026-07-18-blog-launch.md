# Blog Launch: Documentation Site on Material for MkDocs

vouchfx's documentation has migrated to a new Material for MkDocs site. The design, layout, and navigation remain consistent with the previous build, and this blog provides a new home for release notes and engineering write-ups.

<!-- more -->

The documentation site now uses [Material for MkDocs](https://squidfunk.github.io/mkdocs-material/), the popular documentation framework. Readers will find vouchfx's documentation organised in five groups:

**Design docs** — The [Technical Architecture Blueprint](../../01_Technical_Architecture_and_Engineering_Blueprint.md) and [YAML DSL Specification](../../02_YAML_DSL_Specification_and_VSCode_Extension_Design.md) document the engine design, the `.e2e.yaml` language grammar, and the provider model.

**User guides** — A 60-minute [Getting Started](../../getting-started.md) walk-through, guides on [Recipes](../../recipes.md) and [Common Patterns](../../common-patterns.md), a [Troubleshooting](../../troubleshooting.md) section, and the [Language Reference](../../language-reference.md) (generated from the live engine).

**Knowledge base** — Growing collection of deep-dive articles on specific topics. Currently home to the [DCP Orchestrator Portability](../../kb/dcp-orchestrator-portability.md) reference.

**Ecosystem** — [The Ecosystem](../../ecosystem.md) guide covers the Community provider hub, governance tiers, and the provider SDK.

**Project** — [Roadmap](../../roadmap.md), [Changelog](../../changelog.md), [Governance](../../governance.md), and decision records.

URLs from the previous site continue to resolve correctly. This blog will publish release notes for each vouchfx engine release and occasional engineering write-ups on significant features or patterns.
