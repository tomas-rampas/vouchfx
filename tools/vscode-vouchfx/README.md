# vouchfx — VSCode extension

Schema-aware authoring for vouchfx `*.e2e.yaml` integration tests.

This extension binds the **frozen v1 vouchfx JSON Schema** to `*.e2e.yaml`
files so that, inside VSCode, authors get:

- **Completion** — step types and fields offered as you type. The schema uses
  `if`/`then` on the `type` discriminator, so completions are step-type
  specific (e.g. `http.rest` fields differ from `db-assert.postgres` fields).
- **Hover** — the schema carries rich `description`s on every field; hovering a
  key shows its documentation.
- **Inline validation** — invalid keys, wrong types and missing required fields
  are flagged as you edit, before you ever run the suite.

The intelligence itself is provided by the
[Red Hat YAML language server](https://marketplace.visualstudio.com/items?itemName=redhat.vscode-yaml)
(`redhat.vscode-yaml`), which is declared as an **extension dependency** and is
installed automatically alongside this extension. This extension only supplies
the schema and the file-association wiring.

## How the schema is bound

The binding is declarative — see `contributes.yamlValidation` in
`package.json`:

```jsonc
"yamlValidation": [
  { "fileMatch": "*.e2e.yaml", "url": "./src/schema/composed-schema.v1.json" }
]
```

The schema is **bundled with the extension** (no network access required) and
is a byte-for-byte copy of the engine's composed v1 schema. It is the
authoritative, frozen v1 contract and must not be edited here; the canonical
copy is regenerated by the engine and a CI test enforces that the shipped copy
matches it exactly.

## Configuration

| Setting | Type | Default | Description |
| --- | --- | --- | --- |
| `vouchfx.schemaPath` | `string` | `""` | Optional override pointing at an internal/enterprise copy of the composed v1 schema. Absolute, or relative to the workspace root. When empty, the bundled schema is used. |

When `vouchfx.schemaPath` is set, the extension registers programmatically with
the YAML language server (via its `registerContributor` API) and serves the
configured schema for `*.e2e.yaml` files instead of the bundled one. If the
YAML extension is unavailable, activation degrades gracefully and contributes
nothing — it never throws.

## Development

```bash
npm install
npm run compile   # tsc -> dist/, then copies the schema into dist/
npm run lint
npm test          # node:test over the compiled manifest/schema checks
npm run package   # produces vouchfx-<version>.vsix
```

The unit tests run without a full VSCode host: they assert the manifest is
valid and that the bound schema exists, parses and self-identifies as v1.
